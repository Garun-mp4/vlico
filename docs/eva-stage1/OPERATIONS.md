# Eva outbox operation

The existing submission transaction saves Lead and existing notification deliveries. With EVA_CAPTURE_ENABLED=true, it also saves one EvaSyncJob. EVA_SYNC_ENABLED is independent and false by default. Disabling Eva does not disable local forms or email. No old leads are automatically exported.

Configure incoming and partner funnel/status/executor UUIDs separately. Store EVA_API_KEY only in private server environment. The adapter uses a fixed HTTPS host and rejects redirects to prevent key leakage. Raw remote errors are not logged.

Docker Compose provides the separate `eva-delivery` worker. `deliver_eva --watch` drains the queue continuously. A plain `deliver_eva` invocation claims at most one job and is suitable for the existing SpaceWeb cron adapter. Configure `EVA_RESPONSIBLE_ID` with the human assignee; the funnel executor stays the AI agent. Set `EVA_TEST_RECORD=true` only for an isolated local test run. Keep live delivery disabled until the form consent and the production release are approved.

Eva allocates new UUIDs on POST and may reuse a contact by phone or email. The adapter checks the returned phone/email or the submission reference for a Telegram-only contact, and verifies both contact ID and local submission ID on the deal. Eva can reject a new lead for a contact already assigned to the same executor. Such jobs enter review as `existing_contact_lead` so the local request is available for manual handling without overwriting the current CRM stage. A lost POST response or crash before an ID checkpoint enters `write_uncertain` review. Unexpected worker failure is recovered after a 180-second lease. Five exhausted attempts require operator review.

The protected lead detail page shows state and safe error code. Users with change_lead can requeue blocked/review/retry jobs. Requeue preserves returned UUIDs and always rechecks Eva. write_uncertain cannot be requeued; an operator must identify both existing records and run `python backend/manage.py reconcile_eva JOB --contact-id UUID --lead-id UUID`. This command checks ownership without creating records. If only a contact exists, resolve the missing CRM card manually before using this command. Sent jobs cannot be requeued through this action. Verify root cause before retrying; requeue does not delete or edit remote records.

Rollback: disable EVA_SYNC_ENABLED and EVA_CAPTURE_ENABLED, return previous code/adapters if necessary. Retain the additive queue table and all current leads. Do not restore an old database or replay historical Telegram delivery_uncertain records.


Live contract evidence: POST returns top-level items in the inspected account, while GET returns data. skipNotifications belongs to the envelope, not the record. Both shapes supported where documented. Model-attribute names are canonicalized by Eva (underscores removed); the adapter maps UTM names to the canonical names without fabricating missing values. See api-contract-evidence.json.

The site renders the official floating Eva script in both public layouts when EVA_WIDGET_ENABLED=true and EVA_WIDGET_ID is valid. Eva owns the chat UI and transport. `eva-widget.js` adapts Eva's current shadow DOM for a 56 px launcher, cookie panel clearance on mobile, keyboard activation, Escape and focus return. Recheck those interactions if Eva changes its widget. The REST key is server-only. The local reference environment is Docker Compose at http://localhost:8000/ with the existing PostgreSQL and media volumes. Use `docker compose up -d --build --wait web` to rebuild it. Set the widget flags in the hosting environment during the approved rollout and verify a complete chat on the deployed domain.
