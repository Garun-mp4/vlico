Configure incoming and partner funnel/status/executor UUIDs separately. Store EVA_API_KEY only in private server environment. The adapter uses a fixed HTTPS host and rejects redirects to prevent key leakage. Raw remote errors are not logged.

### Первое сообщение по заявке сайта

В Eva используется отдельная задача «VLICO | Артём: первое сообщение по заявке с сайта». У задачи один канал WhatsApp Артёма. Автодобавление контактов, привязка к этапу, повторы и напоминания выключены. Сайт передаёт в задачу одного получателя после создания контакта и лида в Eva. На каждый принятый запрос используется отдельный ключ записи очереди.

- Если выбран WhatsApp или оставлен телефон без предпочтения, сайт готовит одно сообщение по типу формы. Партнёрские заявки, звонки, Telegram и email идут на ручной ответ по оставленному контакту.
- Обработчик `deliver_eva` сверяет результат через 1–3 минуты после постановки и далее при необходимости. Исходящее сообщение Артёма с идентификатором WhatsApp означает, что канал принял сообщение. После ошибки постановки или отправки рабочая почта заявок получает одно отдельное предупреждение со ссылкой и контактом. Если в течение часа результата нет, письмо сообщает о неопределённости. Перед ручным ответом проверьте диалог в Eva. Старые заявки без идентификатора очереди не проверяются заново. Для почтового предупреждения используется `EMAIL_DELIVERY_ENABLED` и `LEAD_NOTIFICATION_EMAIL`.
- Перед запуском проверьте один свой номер, отличный от отправителя. Проверьте текст и повтор той же отправки формы. Примените миграции и задайте `EVA_SITE_OUTREACH_TASK_ID` и `EVA_SITE_OUTREACH_CHANNEL_ID` в окружении сайта и обработчика Eva. Эти параметры действуют только для заявок, поступивших после настройки. Чтобы остановить отправку, поставьте задачу Eva на паузу и очистите оба параметра в окружении. Перед возобновлением проверьте ожидающую очередь.

Eva allocates new UUIDs on POST and may reuse a contact by phone or email. The adapter checks the returned phone/email or the submission reference for a Telegram-only contact, and verifies both contact ID and local submission ID on the deal. Eva can reject a new lead for a contact already assigned to the same executor. Such jobs enter review as `existing_contact_lead` so the local request is available for manual handling without overwriting the current CRM stage. A lost POST response or crash before an ID checkpoint enters `write_uncertain` review. Unexpected worker failure is recovered after a 180-second lease. Five exhausted attempts require operator review.

The protected lead detail page shows state and safe error code. Users with change_lead can requeue blocked/review/retry jobs. Requeue preserves returned UUIDs and always rechecks Eva. write_uncertain cannot be requeued; an operator must identify both existing records and run `python backend/manage.py reconcile_eva JOB --contact-id UUID --lead-id UUID`. This command checks ownership without creating records. If only a contact exists, resolve the missing CRM card manually before using this command. Sent jobs cannot be requeued through this action. Verify root cause before retrying; requeue does not delete or edit remote records.
