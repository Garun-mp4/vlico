# M2 — маршрут заявки на замер

Пункты 7 и 8 [плана](VLADLEN-WIDGET-SALES-PLAN-2026-11-14.md). Настройки внесены в действующую воронку Eva через REST API и повторно прочитаны. Для оператора подготовлена [инструкция](MEASUREMENT-APPROVAL.md). Приёмка M2 открыта до проверки уведомления и одобрения.

## Настройки в Eva

- «Ожидает согласования замера» получает заявку из «Новая заявка», «Квалификация» и «Предварительный расчёт». Условия — явный запрос замера, адрес или район, желаемое время и телефон либо явный выбор ответа в текущем чате. При полном наборе сведений ожидание имеет смысл даже до расчёта. Правило отказа отличает отказ от услуг от отказа от конкретного времени или способа связи.
- Добавлены три необязательных атрибута контакта с доступом Артема на запись — адрес объекта, пожелание по времени и телефон для согласования. Существующее поле «Следующее действие» используется для проверки времени и ответа в исходном чате. [Инструкция канала](knowledge-v2/artem-web-chat.txt) синхронизирована с активной редакцией в Eva.
- Ответственный в проверенных карточках — Владлен, исполнитель — Артем. На стадию «Замер назначен» нет автоматических правил. Артем собирает пожелания, а Владлен проверяет календарь, принимает решение и подтверждает время. Статус до решения не меняется на назначенный.

## Что подтверждено

| Проверка | Результат |
|---|---|
| Два живых диалога в чате сайта, по две реплики с каждой стороны | В обоих случаях одна карточка и одна связанная переписка. Артем отвечал после запроса и оставил подтверждение времени за Владленом. В первом диалоге Артем повторно запросил способ связи. После уточнения инструкции второй диалог прошёл с ответом в чате и без запроса телефона. |
| Источник | Переписка связана с карточкой и указывает канал «VLICO \| Чат сайта». Системное поле источника лида Eva оставляет `unknown`. |
| Автопереход в ожидание | Первый тестовый лид перешёл примерно через 7 мин 49 с после создания карточки, второй через 10 мин 42 с. В обоих случаях сводка диалога указывает переход в ожидание. На момент ручной работы первая карточка уже стояла в ожидании. |
| Поля заявки | В первом диалоге автоматическая сводка записала адрес и сохранила оба предложенных времени в «Следующем действии». Прямое поле пожелания осталось пустым после сводки. Ручная запись через API прошла, но поздняя сводка заменила часть значений. Вторая карточка автоматически получила отдельные адрес, пожелание по времени и следующее действие. Для телефона и сохранения ручных уточнений нужен отдельный контрольный тест. |
| Разрешённые переходы | Считаны обратно три правила в ожидание и ноль правил в «Замер назначен». Ни один запрос не был переведён в назначенный замер. |
| Календарь `VLICO — тест` | Для 16 ноября по Калининграду интервалы 10:00–12:00 и 14:00–16:00 вернулись свободными, 12:00–14:00 — занятым. Проверено чтение через Eva. События не создавались. |
| Сообщение от оператора в том же тестовом чате | Документированный `POST /messages` для синтетического диалога завершился таймаутом. Чтение переписки не нашло эту реплику, повторной отправки не было. |
| Уведомление | У единственного человеческого профиля Eva отсутствуют привязка Telegram и канал уведомлений. У стадии пустой список получателей. Рабочий клиентский бот не использован для теста. |

Живые диалоги запущены браузерной копией страницы с адаптером из M1. Согласованный выезд, календарные события и сообщения реальным контактам не создавались. В кампании все семь задач выключены.

## Что требуется для приёмки

- Подтвердить заполнение всех полей, включая телефон и отдельное пожелание по времени. Проверить защиту ручных уточнений после автоматической сводки. Источник подтверждён в исходном диалоге. Если он нужен отдельным полем отчётности, проверить штатную запись источника с Eva.
- Подтвердить отправку штатного уведомления на контролируемого оператора. Уточнить доступ к отдельному тестовому профилю Гаруна и авторизовать его канал. После проверки отдельно согласовать переключение рабочего получателя.
- Пройти ручное одобрение с тестовым событием без гостей и с репликой оператора в том же чате. Встроенный браузер получил таймаут при открытии Eva, а подтверждение через API в контролируемом диалоге не появилось. В рабочем сценарии использовать проверку календаря и ответ Владлена из кабинета.

Официальная документация Eva — [REST API](https://eva.bz/support/api). Использованы операции для карточек, стадий, правил перехода, атрибутов, сообщений и интервалов Google Calendar.
