## Direction contract

THESIS: понятный подбор одного потолка с честным расчётом известных работ. Operate внутри архитектурного лендинга.

OWN-WORLD: существующие IBM Plex Mono, кремовый canvas, графитовый текст, тонкие линии, прямые углы, зелёный только для состояния выбора. BMW reference используется только для ясного сравнения вариантов и нейтральной иерархии конфигуратора; бренд VLICO приоритетен.

STORY: помещение → размеры → поверхность → примыкание → свет → шторы → монтаж → город → результат без контактов → добровольная отправка специалисту.

FIRST VIEWPORT: единый контур, визуальная левая зона 40%, вопрос и навигация справа 60%. На телефоне вопрос первым, компактная визуализация после полей. Нет фиксированной высоты, вложенных декоративных панелей и тяжёлых анимаций.

FORM: восемь явных шагов в заданной пользователем композиции; без случайного concept seed для точно заданного локального расширения. Переходы только по кнопке, фокус на заголовке, native radio/checkbox и 48px controls.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Архитектура и состояния

Серверный ConfiguratorForm валидирует ответы и зависимости. Модуль расчёта нормализует геометрию и передаёт только известные количества в проверенную Decimal-формулу. Общая фабрика различает прежний API и новую схему v2. Клиент разделён на декларативные данные шагов, модель состояния/видимость/валидацию и контроллер UI. Ни одного клиентского тарифа. Одна конфигурация на форму, sessionStorage версии v2 хранит только параметры, не контакты. При смене вариантов зависимые значения исключаются из расчёта сервером. Навигация назад сохраняет независимые ответы.

Тип помещения — текстовый выбор; размеры — три режима и SVG; поверхность, примыкание и карнизы — визуальный выбор; свет — множественный выбор с условными количествами; монтаж — checkboxes с уточнениями; город — Калининград/область/другое с уточнением. «Нет» и «не знаю» взаимоисключаются с конкретными ответами. Неизвестные количества допустимы. Только прямоугольник в режиме длина/ширина даёт S=L×W и P=2(L+W); сложной форме нужны площадь и необязательный периметр.

Подтверждены только две группы полотна в исходном ассортименте: ПВХ и ткань BAUF. Отдельные сатин/глянец без подтверждённого ассортимента не предлагаются. Неизвестный материал/примыкание или площадь не подменяются выбором клиента. Нет тарифа на люстру, LED отдельно, обычный карниз, обход труб, датчики, плитку, многоуровневость, выезд; они сохраняются и показываются как уточнения. Контур парящего профиля не тарифицируется повторно. Нет подтверждённой матрицы совместимости ткани с теневым/парящим профилем: стоимость такого сочетания требует проверки специалиста. Не придумываем минимальную сумму или коэффициенты.

Результат: состав, выбранные ответы, отмеченные исключения, известная часть суммы либо индивидуальный расчёт при неизвестной основе. Тарифы всегда названы предварительными. Статусы запроса, ошибки, повтор, 409 при смене ставок, подтверждение БД до success. Снимок конфигурации доступен кабинету и Telegram. Контактная форма использует существующий pipeline, собственные уникальные IDs на главной.

## Ресурсы и проверка

Существующие иллюстративные материалы сайта: light-lines.jpg, magnetic-tracks.jpg, penthouse-chandelier.jpg, cornice.jpg. Их наличие в репозитории не доказывает, что это выполненные компанией объекты. Для принципиальных узлов — SVG-сечения с подписью «схема», не фото объекта. Матовый ПВХ и ткань — ImageGen illustrations, подпись и provenance отдельно. Оптимизированный WebP, заданные размеры, lazy loading.

Регрессии: прежние контрольные суммы; прямоугольник/площадь/неизвестные размеры; неизвестные количества; снятие света; exclusive answers; геометрия; ткань/профиль; парящий + LED без повторной строки; заявки с полным снимком, повтор и устаревшая версия. Браузер: восемь шагов, назад, результат, форма, ошибки сети, размеры 1440/1280/1024/768/390/320, no overflow, клавиатура, reduced motion, no-JS. Django suite/check и Docker build.

## Карта изменений

Сохраняются URL, тарифы и версии, серверная арифметика, кабинет/заявки/вложения/атрибуция. Заменяются непрерывная форма и клиентский код расчёта новым общим модулем. Удаляются старый layout и ветви leads.js после проверки. Добавляются главная секция, восемь шагов, SVG геометрия, условные уточнения, сводка и явные неопределённости. Новые зависимости не требуются.
