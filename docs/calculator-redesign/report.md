# Отчёт о переработке калькулятора

## 1. Исходное состояние

Старая страница `/calculator/` была одной технической формой с площадью, материалом, профилем, периметром, количеством света и длинами систем. Аудит, формулы и контрольные примеры сохранены в as-is.md; снимки 1440 и 390 px — в screenshots/before-*.png. Сохранены версии тарифов, серверная арифметика Decimal, кабинет, вложения, атрибуция, согласие и защита повторов.

## 2. Положение на лендинге

Было: Hero → о компании → проекты → системы → процесс → контакты. Стало: Hero → о компании → проекты → системы → **калькулятор (пятый)** → процесс → контакты. Посетитель сначала знакомится с работами и решениями, затем выбирает своё, после расчёта узнаёт порядок замера и монтажа. Навигация на главной и других страницах, ссылка в контактах и дополнительный текстовый CTA Hero ведут на `/#calculator`. Контекстные CTA услуг и обсуждения проекта сохранены. Якорь имеет отступ под фиксированную навигацию, native history и reduced motion.

## 3. UX

Восемь этапов: помещение, размеры и форма, материал, примыкание, свет, карнизы, монтаж, расположение. Текстовый выбор, фото, схемы, multiselect, счётчики и числовой ввод применяются по смыслу. Количества можно не знать. Условные поля: другое помещение, способ ввода/форма, количества выбранного света, длина карниза, трубы и датчики, населённый пункт. Ответы «нет»/«не знаю» исключают конкретные ответы. Снятые варианты перестают влиять на смету. Назад сохраняет независимые ответы; sessionStorage v2 хранит только конфигурацию. Новый расчёт запускается явной кнопкой сброса. Многокомнатной сметы нет.

## 4. UI

Общий шаблон секции, двухколоночный shell 40/60, индикатор 1–8, вопросы, visual panel, схемы, сводка, результат и раскрываемая форма связи. Использованы существующие IBM Plex Mono, кремовый/песочный фон, графит, тонкие границы и прямые углы. Выбор отмечен доступным зелёным состоянием. На мобильном вопрос и ответы предшествуют компактной визуализации; нет фиксированной высоты и перекрывающей навигации. Видимые focus, error, disabled, loading и success states. Геометрия SVG использует общую шкалу длины/ширины и подписанные реальные значения; для сложной формы прямоугольные формулы не применяются.

## 5. Изображения

Подробности и полные промпты — в assets.md. ImageGen создал иллюстрации матового ПВХ, ткани и точечных светильников, сохранённые в `wireframe/assets/calculator/` как WebP. Для света и скрытого карниза используются соответствующие иллюстративные материалы сайта; конструктивные узлы показаны SVG-сечениями. Генерации помечены в предпросмотре и не выдаются за выполненные объекты. Требуется обычное подтверждение соответствия реальным образцам и профилям специалистом компании.

## 6. Расчёт

`core/configurator.py` валидирует ответы, исключает зависимые поля и нормализует геометрию; `core/pricing.py` остаётся единственной арифметикой и источником ставок через активную PricingVersion в БД. Тарифы в клиентский JavaScript не копируются. Существующие контрольные суммы 16240 и 50900 ₽ сохранены. На клиенте вычисляются только размеры SVG, не стоимость.

При неизвестной площади или материале суммы нет: индивидуальный расчёт. Неизвестный периметр, количества, сложная геометрия и неоценённые работы явно перечисляются; показана только известная часть стоимости. Контур парящего профиля не создаёт отдельной платной LED-строки. Ткань с теневым/парящим профилем требует подтверждения совместимости. Для люстр, отдельного LED, обычного карниза, труб, датчиков, плитки, уровней и выезда нет отдельного подтверждённого тарифа: он не придуман. Минимальная стоимость и коэффициенты не введены. Ставки, как и до переработки, предварительные для согласования.

## 7. Интеграции

Главная и `/calculator/` используют один модуль, старый URL не удалён. API поддерживает новую схему v2 и прежние параметры для обратной совместимости. Заявка проходит существующий транзакционный pipeline, сохраняет полные ответы, версии, позиции и предупреждения. Кабинет и Telegram читают этот снимок. При смене тарифов возвращается 409, новая сумма требует повторного подтверждения. Идемпотентность и подписи формы сохранены. Серверная отправка работает без JavaScript. База и Compose-схема не менялись, миграций данных не потребовалось. Локальные контейнеры web/delivery пересобраны; публичный сервер не развёртывался.

## 8. Архитектура

Новые файлы: `core/configurator.py`, `core/test_configurator.py`, `core/static_storage.py`, `templates/site/calculator-section.html`, `static/calculator/{model,view,controller}.js`, `static/configurator.css`. Изменены home/base/calculator, lead-fields, quote, cabinet/lead, lead_views, lead_service, telegram_delivery, views, settings и DESIGN.md. Старый клиентский калькулятор из leads.js и прежние layout-стили удалены. Старый шаблон страницы теперь только подключает общий модуль. Static manifest теперь версионирует также импорты ES modules. Новых runtime-зависимостей нет; npm-сборка не нужна.

## 9. Проверки

Выполнены Docker build/up, `python manage.py test core --noinput`, `python manage.py check`, `node scripts/test-calculator-model.mjs`, `node --check` для изменённых JS, `git diff --check`. Все 80 серверных тестов прошли. Серверные тесты используют отдельную временную test-БД, реальные данные не удалялись. Первая попытка в одноразовом контейнере без collectstatic выявила отсутствие манифеста статики; после корректной подготовки окружения suite прошёл.

Браузер через playwright-cli: полный путь восьми этапов с контрольной суммой 50900 ₽, назад с сохранением размеров, форма после результата, отсутствие duplicate IDs, ширины 1440/1280/1024/768/390/320, отсутствие horizontal overflow. Отдельно: неизвестная база без вымышленной суммы, потеря сети при расчёте и успешный повтор, серверная форма с отключённым JS и десятичной запятой (17720 ₽), reduced-motion. Ошибка/повтор/подтверждение формы в браузере проверены с перехватом транспорта; эта проверка не отправляла внешние уведомления. Реальная запись заявки, полный snapshot, повтор, stale rates и вложения проверены Django-тестами. Сценарии можно повторить:

```
playwright-cli -s=vlico open http://127.0.0.1:8000/
playwright-cli -s=vlico run-code --filename=scripts/test-calculator-browser.js
playwright-cli -s=vlico run-code --filename=scripts/test-calculator-errors.js
```

Снимки после изменений находятся в screenshots/after-*.png. Визуальный проход проверил контраст, состояния, desktop/mobile и соответствие DESIGN.md. Механический Impeccable detector нашёл только advisory по дополнительным цветам; их назначения задокументированы в DESIGN.md. Преднамеренные сетевые ошибки в негативном браузерном сценарии не являются необработанными исключениями приложения.

## 10. Итог и границы

Готовы общий модуль, главная секция, восемь этапов, схемы, сохранение ответов, серверный расчёт, результат, форма, обработка старого URL и кабинета. Обязательны подтверждение коммерческого прайса и тарификации дополнительных работ, ассортимента фактур, матрицы совместимости профилей/ткани и конкретных образцов. После уточнения пользователя добавлены сатин и глянец как пожелания с подтверждением доступности и индивидуальной стоимости. Подробнее о сравнении четырёх поверхностей: material-comparison.md.

Не проверены физические телефоны, другие браузерные движки и доставка новой конфигурации в реальный Telegram; формат сообщения и очередь покрыты существующими тестами, внешнее тестовое сообщение не отправлялось. Реальный публичный запуск, юридические сведения и утверждение ставок остаются бизнес-этапом проекта. Это готовая интеграция в локальный сайт с честно ограниченной оценкой, а не подтверждение окончательного коммерческого прайса.
