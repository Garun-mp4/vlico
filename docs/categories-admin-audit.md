# Категории и аудит админки, 04.11.2026

## Реализовано

- ProjectCategory и несколько категорий на проект, шесть начальных направлений из клиентского перечня.
- Создание/редактирование/порядок/удаление в кабинете. Удаление с подтверждением сохраняет проекты, медиа и другие связи. Регистр имени учитывается как одна категория; пустые и повторяющиеся названия отклоняются.
- Категории независимы от Service. Они отображаются в карточках/кейсе и фильтрах каталога, статус и категория совместно фильтруются в кабинете.
- Причина пропажи проектов с главной: условие featured=True и ограничение тремя записями. Главная теперь получает все опубликованные проекты в заданном порядке, поле featured убрано из формы. Черновики и архив не отображаются.
- Права управления категориями выданы действующей группе редакторов миграцией. Начальные категории создаются один раз; удалённые пользователем категории не восстанавливаются при запуске.

## Проверки

- Django check: без ошибок. makemigrations --check --dry-run: изменений нет. Полный набор: 37 тестов, OK.
- Регрессии: шесть начальных категорий; CRUD и дубликаты с разным регистром; stale revision; удаление категории с опубликованным проектом и фото; права гостя/обычного пользователя/редактора без специальных прав, CSRF и методы; несколько категорий при сохранении; публичные и административные фильтры; неверный category ID; публикация без featured и отображение более трёх проектов; отсутствие черновиков после снятия/архивирования; неверная категория и повторный slug.
- Существующие серверные проверки: вход/выход/лимит попыток, права, CSRF, устаревшая форма, публикация/предпросмотр, приватность media/source, файлы и лимиты, обложка, порядок, подписи, удаление, версии изображения, повтор загрузки без дубля, сохранность исходника. Добавлены проверки лимита 40 фотографий и изоляции тестового private storage.
- Playwright: реальный вход; категория create/edit/duplicate/delete; новый проект с двумя категориями; пакет из двух фото с редактором; смена обложки и порядка; подписи; повторная правка/reset; preview и клавиатурная галерея; публикация с проверкой HTML главной, каталога и sitemap; совместный фильтр; удаление связанной категории без потери проекта; снятие с публикации, архив и восстановление; удаление фото; выход и проверка закрытого доступа гостю.
- Негативные браузерные сценарии: неверное изображение; быстрый skip с намеренно отложенным decode; обрыв сетевого запроса, сохранение введённой подписи и успешный повтор без дубликата. В консоли отрицательного сценария ожидаемо присутствует искусственный network abort; в обычном сценарии ошибок не было.
- Визуально проверены категории, форма проекта и публичный фильтр на desktop/mobile. Ширины 320, 390, 768 и 1280: редактор проекта и список категорий без горизонтального переполнения. Длинные названия переносятся.
- Docker image пересобран, web пересоздан и оба сервиса healthy. Созданная для проверки категория после удаления не вернулась при запуске. Связи и клиентские данные сохранились. Тестовые объекты и их файлы удалены.

## Исправления аудита

1. Автоматическое появление опубликованных проектов на главной вместо скрытого переключателя.
2. Исключение результата старого async decode после skip/закрытия окна, чтобы он не подменял следующий кадр.
3. Динамическое private storage и временный public/private root в тестах, чтобы тестовые исходники не попадали в рабочее хранилище.
4. Адаптивная навигация кабинета и перенос длинных названий категорий.

Разработка и проверка выполнены в локальной Docker-версии. Старый статический Vercel-preview не является серверной публикацией. CRM, заявки и калькулятор остаются последующими этапами, а не частью админки портфолио.
